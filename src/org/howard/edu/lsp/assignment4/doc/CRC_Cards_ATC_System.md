## CRC Cards — Air Traffic Control (ATC) System

---

CRC Card
Class: Transponder
Responsibilities:
- Encode aircraft type and flight data into a high-density packet
- Broadcast the encoded packet at regular intervals
- Assign a unique identifier to each transmission
Collaborators (if any):
- FlightDataPacket
- Aircraft
Assumptions (if any):
- Each aircraft carries exactly one transponder
- Transponders broadcast continuously while the aircraft is in range

---

CRC Card
Class: Aircraft
Responsibilities:
- Store aircraft type (e.g., commercial, cargo, private)
- Store current flight data (position, altitude, speed, heading)
- Provide flight data to the transponder for encoding
Collaborators (if any):
- Transponder
Assumptions (if any):
- Aircraft identity is represented by a unique flight ID (e.g., tail number or callsign)
- Flight data is updated in real time from the aircraft's onboard instruments

---

CRC Card
Class: FlightDataPacket
Responsibilities:
- Store encoded flight data fields (flight ID, aircraft type, altitude, speed, heading, position)
- Provide decoded field values to the ground receiver upon request
- Validate packet integrity (e.g., checksum)
Collaborators (if any):
- GroundReceiver
Assumptions (if any):
- Packets are transmitted in a fixed high-density binary format
- A packet contains exactly one snapshot of an aircraft's state at a point in time

---

CRC Card
Class: GroundReceiver
Responsibilities:
- Receive incoming broadcast packets from aircraft transponders
- Unpack and decode FlightDataPacket fields
- Forward decoded aircraft data to AircraftDatabase for storage
Collaborators (if any):
- FlightDataPacket
- AircraftDatabase
Assumptions (if any):
- The ground station is capable of receiving signals from all aircraft within airport airspace
- Packets arrive asynchronously and are processed as they are received

---

CRC Card
Class: AircraftDatabase
Responsibilities:
- Store and index aircraft records by flight ID
- Update an existing aircraft record when new flight data arrives
- Retrieve a single aircraft record by flight ID upon query
- Provide the full list of currently tracked aircraft to other components
Collaborators (if any):
- Aircraft
- GroundReceiver
- RadarDisplay
- HazardAnalyzer
- ControllerConsole
Assumptions (if any):
- The database holds only aircraft currently active in the airspace
- Records are replaced (not appended) when updated data arrives for the same flight ID

---

CRC Card
Class: RadarDisplay
Responsibilities:
- Retrieve current aircraft data from AircraftDatabase
- Render aircraft positions and identifiers on a graphical screen
- Refresh the display every 10 seconds
- Highlight aircraft flagged as hazardous by HazardAnalyzer
Collaborators (if any):
- AircraftDatabase
- DisplayTimer
- HazardAnalyzer
Assumptions (if any):
- The display uses a 2D top-down radar view
- Each aircraft is shown with its flight ID and current position marker

---

CRC Card
Class: DisplayTimer
Responsibilities:
- Track elapsed time since the last display refresh
- Notify RadarDisplay to trigger a refresh every 10 seconds
Collaborators (if any):
- RadarDisplay
Assumptions (if any):
- The timer runs on a dedicated background thread
- The 10-second interval is fixed and not configurable at runtime

---

CRC Card
Class: HazardAnalyzer
Responsibilities:
- Retrieve all current aircraft records from AircraftDatabase
- Calculate separation distances between aircraft pairs
- Detect when two or more aircraft violate minimum safe separation thresholds
- Flag hazardous aircraft and notify ControllerConsole with an alert
Collaborators (if any):
- AircraftDatabase
- ControllerConsole
Assumptions (if any):
- Minimum safe separation thresholds (horizontal and vertical) are predefined constants
- Analysis runs each time the display refreshes (every 10 seconds)

---

CRC Card
Class: ControllerConsole
Responsibilities:
- Accept flight ID queries entered by the controller
- Request detailed aircraft data from AircraftDatabase
- Display retrieved aircraft details to the controller
- Receive and present hazard alerts generated by HazardAnalyzer
Collaborators (if any):
- AircraftDatabase
- HazardAnalyzer
Assumptions (if any):
- The console is operated by a single human air traffic controller
- Queries are entered manually via keyboard input
